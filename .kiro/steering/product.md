# 제품 — Tripwire

Kiro 스펙의 수용 기준(EARS)을 실행 가능한 속성 검사로 바꿔, 코드나 자율 에이전트가 스펙을 벗어나는 순간 최소 반례로 잡는다. 에이전트의 다음 쓰기는 막고, 사람에게는 고칠 길(스펙을 고친다 / 코드를 되돌린다)을 보여 준다.

## 사용자

Kiro로 스펙 주도 개발을 하는 개발자와 팀. 특히 스펙 작업 일괄 실행이나 CLI 무인 실행처럼 에이전트에게 작업을 길게 맡기는 사람.

## 흐름

1. 색인 — `guard scan`이 `.kiro/specs/*/requirements.md`의 수용 기준을 `Rn.m`(스펙이 여럿이면 `<spec>:Rn.m`)으로 색인한다. 문장 끝의 `(근거: …)`는 선택 항목 basis로 읽는다
2. 검사 만들기 — 에이전트가 수용 기준마다 fast-check 속성 검사를 쓴다. 테스트 이름은 `[Rn.m]`으로 시작한다
3. 검사의 검사 — 에이전트가 그 기준만 어긴 변형 구현(변형 JSON)과 실행할 명령 줄을 만들고, 사람이 `guard adopt`를 실행해 변형에서 실패하는 검사만 채택한다. 채택된 검사는 `.kiro/guard/sealed.json`에 봉인된다
4. 감시 — 에이전트가 파일을 쓰거나 셸을 실행한 뒤 `guard check`가 판정을 갱신한다. 빨강이고 사람의 해결 승인이 없으면 `guard gate`가 다음 쓰기·셸 실행을 종료 코드 2로 막는다
5. 해결 — 사람만 고른다: 스펙을 고친다(`edit-spec`) 또는 코드를 되돌린다(`revert-code`). 기록은 `guard resolve` 또는 화면의 버튼으로 한다
6. 화면 — `guard serve`가 요구사항과 코드 줄을 잇는 실, 에이전트 활동, 반례 찾기 과정을 1920×1080 한 화면에 보여 준다

## 판정 — 코드만 한다

| 판정 | 조건 |
|---|---|
| 빨강 | 연결된 검사 중 하나라도 실패(첫 실패의 최소 반례를 기록), 또는 봉인된 검사 파일의 내용이 바뀜(`seal-broken`) |
| 노랑 | 연결된 검사가 없음(`no-tests`), 또는 검사를 봉인한 뒤 요구사항 문장이 바뀜(`stale`) |
| 초록 | 연결된 검사가 1개 이상이고 모두 통과 |

전체 판정은 빨강이 하나라도 있으면 빨강, 아니면 노랑이 있으면 노랑, 아니면 초록이다. 정확한 우선순위와 출력 형식은 각 스펙이 기준이다.

## 원칙

- 판정은 결정적인 코드만 한다. AI(Kiro 에이전트)는 검사·변형 구현·스펙 수정안을 만들 뿐 판정하지 않는다
- 결정은 사람만 한다. 에이전트는 해결 승인·봉인 목록·hook 정의를 쓰지 않고, 봉인(`guard adopt`)과 해결 기록(`guard resolve`)을 실행하지 않는다 — 실행할 명령 줄을 사람에게 보여 준다
- 판정이 미치는 범위는 hook이 실행되는 Kiro IDE와 CLI다
- 시연 대상은 `demo/`의 회원가입 검증 모듈(수용 기준 6개)이다
