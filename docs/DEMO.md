# LERO AI Agent 3분 데모 — KIROTHON 당일 전체 시간표

[서비스 열기](https://ai-hackathon.cloud) · [검증 상태](../README.md#7-테스트)

메인 흐름은 **공식 URL → 오늘 전체 시간표 → 검토·승인·저장 → 자료의 일정 모두 Calendar 반영 → 실제 9개 확인 → 대화로 오늘 일정 조회**다. Drive는 선택 시연으로 남긴다.

## 발표 전 준비

- 발표 계정 로그인과 Calendar Google 동의·콜백을 미리 끝낸다. LERO와 같은 계정의 Google Calendar를 탭으로 열고 한국 시간대(KST)의 오늘인 **2026-11-14**를 맞춘다.
- 앱의 링크 입력에서 제목은 **`KIROTHON 2026 당일 전체 타임테이블`**, URL은 **`https://kirothon.ausg.me/`**를 사용한다. 행사 일부만 추리는 대신 오늘의 시간대 **9개 전체**가 들어왔는지 확인한다.
- v9에서 실제 생성된 결과는 시간대 9개와 할 일 2개다. 신청·제출 마감 1개는 원문 사실로 확인하고, 이미 지난 AI 준비 추천 1개는 선택을 해제한다. 과거 신청 마감을 미래 업무로 소개하지 않는다.
- 당일 전체 시간표 흐름은 실제 계정으로 검증했다. 9개 시간대와 할 일 2개 중 지난 AI 준비 추천을 빼고 10개를 승인했으며, Calendar 일괄 등록은 **9건 성공·0건 실패**였다.
- 검증 후 승인된 테스트 일정 9개만 삭제하고 Google 오늘 화면이 다시 **0건**임을 확인했다. LERO 자료·초안·항목·메일 중복 표식도 비공개 백업 후 0건으로 초기화했고, 로그인·서비스 연결·대화는 보존했다. 발표는 새 대화와 깨끗한 자료 화면에서 시작한다.
- 개인 Gmail은 열지 않고 자동 수집은 끈다. 저장된 동일 공식 원문·승인 계획과 검증 화면을 예비 탭으로 준비한다.

## 0:00–3:00 진행표

| 시간 | 화면·동작 | 짧은 설명 |
|---|---|---|
| 0:00–0:15 | LERO 링크 입력 화면 | “행사 공지에는 하루 전체 시간표와 마감이 함께 있습니다. 이를 검토 가능한 일정과 할 일로 바꾸겠습니다.” |
| 0:15–0:45 | 제목 `KIROTHON 2026 당일 전체 타임테이블`, URL `https://kirothon.ausg.me/` 입력 → 분석 | “공식 페이지를 직접 읽습니다.” 분석 대기 시간을 확보한다. 한 번의 사전 분석에서는 11.79초가 관측됐으며 응답 시간을 보장하는 수치는 아니다. |
| 0:45–1:20 | 당일 시간대 9개·마감 1개, 원문 근거·AI 추천·날짜 질문 확인 | “오늘 시간표 전체가 들어왔는지 원문과 대조합니다.” 이미 지난 준비 추천은 선택을 해제한다. 질문이 있을 때만 보여 주고, 임의 날짜를 채우지 않는다. |
| 1:20–1:40 | 선택 항목 검토 → 승인·저장 | “제가 확인하고 승인한 계획을 저장합니다.” |
| 1:40–2:15 | 자료 화면의 **이 자료의 일정 모두 Calendar에 반영** 버튼 → 처리 결과 확인 | “이 자료에서 승인한 일정 9개를 한 번에 반영합니다.” 성공·실패 개수를 실제 응답으로 확인한다. |
| 2:15–2:35 | Google Calendar 오늘 화면 → 9개 일정 확인 | 검증 전 빈 화면과 현재 결과를 구분한다. 실제 오늘 일정 9개가 생성됐는지 확인한다. |
| 2:35–2:55 | 대화에 아래 문장을 그대로 입력 | “이제 연결한 Google Calendar의 오늘 일정을 대화로 조회합니다.” KST의 시간·제목과 총 9개가 응답에 나타나는지 확인한다. |
| 2:55–3:00 | 일정 결과 화면 | “공지를 읽고, 제가 승인한 전체 계획을 실제 서비스에 반영한 뒤 다시 확인할 수 있습니다.” |

대화 입력은 다음 문장을 **그대로** 사용한다.

~~~text
구글 캘린더에 오늘 일정 있어?
~~~

이 흐름은 실제 계정으로 확인했다. 결과는 **한국 시간 기준 오늘 일정 9개**, **HH:MM 시간 구간과 제목**, **총 개수 9개**였고 새로고침 뒤에도 같은 대화 ID가 유지됐다. 발표 중에는 현재 실행의 실제 결과를 다시 확인한다.

## 네트워크가 느릴 때

분석·일괄 등록·조회가 늦으면 예비 탭의 저장된 동일 공식 원문과 승인 계획으로 이동한다. **“지금 응답을 기다리는 중이라 사전 검증 때 저장한 같은 자료로 이어 보여드리겠습니다.”**라고 설명한다.

검증 전 빈 Calendar 화면은 과거 캡처임을 밝히고, 실제 현재 결과와 구분한다. 등록 성공을 확인하지 못했다면 성공했다고 말하지 않으며, 응답이 늦다는 이유로 일괄 등록을 반복하지 않는다.

## 선택 시연

- **Drive:** 메인 발표 후 시간이 남으면 공개 합성 파일 `LERO-테스트-워크숍-공지`의 대화 검색·선택·가져오기와 원문 후속 질문을 보여 준다. 이는 이미 실계정으로 3개 항목 분석·승인까지 확인한 별도 흐름이다.
- **Tasks:** 테스트 준비 항목 생성과 대화 완료 후 원격 완료 반영은 별도 검증된 기능이다. 메인 당일 시간표 시연에 추가 등록을 섞지 않는다.
- **Model Armor:** 별도 대화에서 사전에 검증한 합성 공격 문구와 차단 응답을 보여 줄 수 있다. 앱 런타임 계정의 정상 공식 공지 ALLOW·분석은 확인했다. 인증 사용자로 한국어·영어 정상/공격 텍스트, 정상 PNG, 정상/공격 PDF를 확인했으며, 런타임 계정의 공격 차단 장면은 확인된 경우에만 시연한다.

## 질문을 받으면 설명할 범위

- 서버가 허용한 도구와 본인 자료를 사용하며, 계획 승인은 명시적 동작이다.
- Gmail은 설정한 검색 조건에서 새 메일 최대 10건을 확인한다. 분류 추가 전 실제 3건 → 초안 3개를 검증했다. 선택적 Cloud AI 분류를 포함한 실제 메일 검증은 대기 중이며 발표 중 개인 메일을 사용하지 않는다.
- 백엔드 전체 검사 **366개가 통과**했다. 최종 제출본의 봉인 검사 2개도 기준별 fast-check 100회로 통과했다. 실제 Kiro SessionStart·ICS 소스/검사 쓰기·pytest 셸·PostToolUse 두 기준 green 호출은 확인했다.
- LERO의 스펙 위반 후 작업 차단, 전체 Google 권한 검증 완료, 프로덕션 공격 UI 차단은 확인한 범위로 확장하지 않는다. 정상 공식 공지의 런타임 ALLOW 경로와 인증 사용자의 공격 템플릿 검사 결과를 구분한다.
