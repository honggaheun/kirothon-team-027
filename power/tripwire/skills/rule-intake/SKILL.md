# rule-intake — 한 문장 규칙을 기준과 검사로

`<guard>`: `.kiro/hooks/tripwire.json`의 command에서 하위 명령 앞부분(예: `node ../guard/dist/cli.js`).

## 0. 시작 조건

- 전체 판정이 빨강이면 먼저 resolve-violation을 따른다. 빨강인 동안은 쓰기가 막혀 있다.
- 기존 기준을 바꾸거나 지우는 요청은 이 스킬의 일이 아니다. 그것은 스펙 수정이고, 사람이 결정한다(resolve-violation의 '스펙을 고친다' 흐름과 같은 확인을 거친다).

## 1. 받기와 확인 질문

입력은 한 문장이다(예: "비밀번호에는 특수문자가 하나 이상 있어야 해요"). 문장만으로 측정할 수 없는 빈칸이 있을 때만 묻고, 질문은 한 번에 모아 두 개 이내로 한다.

- 숫자·단위·경계(미만/이하/이상/초과), 대상 입력, 결과(거절/허용)
- 용어의 범위(예: "특수문자"가 어떤 문자들인가)
- 어느 스펙의 어느 요구사항 묶음에 넣을지(모르면 제안한다)
- 법·정책 근거가 있는지 — 있으면 사람이 정확한 출처(법 이름·조·항)를 준다

## 2. EARS 제안 [사람 확인]

- **형식**: 그 스펙의 기존 문장과 같은 꼴로 쓴다. 예: `N. WHEN 비밀번호에 특수문자(!@#$%^&*)가 하나도 없으면 THEN 시스템은 가입을 거절해야 한다(SHALL)`. 근거가 있으면 문장 끝에 `(근거: <사람이 준 출처>)`를 붙인다.
- **측정 가능하게**: 숫자·경계·대상을 명시한다. 조건 하나에 결과 하나. '적절히·충분히·빠르게·안전하게'처럼 잴 수 없는 말은 쓰지 않는다.
- **자리**: 맞는 요구사항 묶음의 수용 기준 **맨 뒤**에 다음 번호로 붙인다. 맞는 묶음이 없으면 문서 **맨 뒤**에 새 `Requirement N`(문서가 한국어 제목을 쓰면 `요구사항 N`)을 User Story 한 줄과 함께 만든다. 기존 번호 사이에 끼우거나 번호를 바꾸지 않는다 — ID는 순서로 매겨지므로 뒤의 ID와 검사 태그·봉인이 모두 어긋난다.
- **충돌 확인**: 기존 기준과 모순되거나 겹치면 알린다. 이 규칙을 지키려면 기존 기준을 바꿔야 한다면 여기서 멈추고 사람이 결정하게 한다.
- **보여 줄 것**: `requirements.md`에 들어갈 diff, 새 ID(`<spec>:RN.m`), 기존 기준과의 관계, 그리고 "코드도 지금 이 기준에 맞게 고칠까요?"
- 승인 전에는 아무것도 쓰지 않는다.

## 3. 쓰기

1. 승인된 문장을 글자 그대로 `requirements.md`에 덧붙인다.
2. 쓰기 후 검사로 새 ID가 노랑(`no-tests`)으로 나타나는지 `.kiro/guard/report.json`을 파일 읽기 도구로 읽어 확인한다(`<guard> check`를 셸로 직접 실행하는 것은 guard를 개발하는 저장소에서만 — 설치된 guard는 문지기가 막는다).

## 4. 코드와 검사

- **코드도 지금 고치기로 했으면**: 새 기준을 지키도록 코드를 먼저 고친 뒤 property-tests 스킬로 검사를 만든다. 검사를 먼저 쓰면 현재 코드에서 실패해 그 순간 빨강이 되고, 집행 모드에서는 다음 쓰기가 막힌다. 고치기 전 코드의 해당 부분은 새 기준을 어기는 자연스러운 변형이므로, check-the-checks의 변형 하나로 써도 된다.
- **코드는 나중에 고치기로 했으면**: 검사를 아직 쓰지 않고 노랑(`no-tests`)으로 둔 채 보고한다.
- 검사가 현재 코드에서 실패하면 검사를 고쳐 통과시키지 않는다. property-tests 5단계대로 판단한다.
- 통과하면 check-the-checks 스킬로 변형 JSON을 만들고, 봉인할 `<guard> adopt <spec>:<Rn.m> --test <검사 파일> --mutant <변형 JSON> …` 명령 줄을 사람에게 보여 준다. 봉인은 사람이 실행한다 — 에이전트는 adopt를 실행하지 않는다(인자 없이도).

## 5. 근거 규칙

- 근거는 사람이 준 출처만, 받은 표기 그대로 적는다(예: `(근거: 개인정보 보호법 제22조의2 제1항)`).
- 조문 번호를 추측하거나 보태지 않는다. 출처를 지어내지 않는다. 기억에 기대 법 내용을 단정하지 않는다. 출처가 불분명하면 묻는다.
- 근거는 검사의 기준값이 아니다. 검사는 문장의 조건과 결과에서 만든다.

## 6. 보고

새 ID, 확정된 문장(근거 포함), 고친 코드(있으면), 검사 파일, 변형과 잡음 여부, 봉인 여부, 현재 판정.
